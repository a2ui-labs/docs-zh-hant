# A2UI 適合誰？

適合那些要打造具備豐富、可互動 UI 的 AI 智慧體的開發者。

## 三類受眾

### 1. 宿主應用開發者（前端）

建立多智慧體平台、企業助理，或讓智慧體負責生成 UI 的跨平台應用。

**為什麼選 A2UI：**

- 品牌控制：客戶端掌握樣式與設計系統
- 多智慧體：支援本地、遠端與第三方智慧體
- 安全：宣告式資料，不執行程式碼
- 跨平台：Web、行動端、桌面端
- 可互通：開源，同一份規範可搭配多個渲染器

**開始使用：** [客戶端設定](../guides/client-setup.md) | [主題與樣式](../guides/theming.md) | [自訂元件](../guides/authoring-components.md)

### 2. 智慧體開發者（後端 / AI）

建立能生成表單、儀表板與互動式工作流程的智慧體。

**為什麼選 A2UI：**

- 對 LLM 友善：扁平結構，易於增量生成
- 互動更豐富：不只文字，還有表單、表格與視覺化
- 屬於生成內容而不是工具呼叫：UI 本身就是智慧體輸出的一部分
- 可攜：同一份智慧體回應可在所有 A2UI 客戶端上運作
- 可串流：生成的同時即可進行漸進式渲染

**開始使用：** [智慧體開發](../guides/agent-development.md)

### 3. 平台建構者（SDK 建立者）

建立智慧體編排平台、框架或 UI 整合方案。

你是否需要把遠端智慧體帶進你的應用？

你是否需要把自己的智慧體部署到不一定由你控制的其他應用中？

**為什麼選 A2UI：**

- 標準協議：可與 A2A 及其他傳輸層互通
- 可擴充：支援自訂元件目錄
- 開源（Apache 2.0）

**開始使用：** [社群](../ecosystem/community.md) | [路線圖](../roadmap.md)

## 何時適合使用 A2UI

- ✅ **智慧體生成 UI** - 核心用途
- ✅ **多智慧體系統** - 可跨信任邊界使用的標準協議
- ✅ **跨平台應用** - 一個智慧體，多個渲染器（web / mobile / desktop）
- ✅ **高度重視安全** - 宣告式資料，不執行程式碼
- ✅ **品牌一致性** - 由客戶端掌控樣式

- ❌ **靜態網站** - 請使用 HTML / CSS
- ❌ **單純文字聊天** - 請使用 Markdown
- ❌ **與客戶端未深度整合的遠端元件** - 請使用 iframe，例如 [MCP Apps](../introduction/agent-ui-ecosystem.md)
- ❌ **需要快速把 UI 與智慧體一起搭起來的應用** - 請使用 [AG-UI / CopilotKit](../introduction/agent-ui-ecosystem.md)

詳細比較請參閱 [智慧體 UI 生態](../introduction/agent-ui-ecosystem.md)。
